# Compute pipeline conformance corpus

The executable half of [`../PIPELINE_WIRE.md`](../PIPELINE_WIRE.md). An implementation in any language
certifies by running every vector this corpus lists.

## Layout

```
manifest.json     the authoritative enumeration: the families, the reserved family, the schema, and
                  every vector with its kind, its file's sha256 and, where it has one, its digest
emit.mjs          a second, dependency-free emitter written from the text alone (§9.6)
validate.mjs      index, schema and rule checks, and that every reject vector is refused
pipeline/         whole pipelines: worked examples, the encoding's edge cases, document-level
                  reject and accept vectors
step/             one vector per step kind, every optional member present
expr/             one vector per expression kind
cell/             one vector per cell kind; the cell texts' reject and accept vectors
slot/             each slot type, as a literal and as a parameter
token/            every registry token, and every column type as a cast target
source/           a source by reference and an embedded one
```

**Counts are not written here.** `manifest.json` is the enumeration; a number in prose drifts from the
directory beside it, and the manifest cannot.

## Reading a fixture

**A fixture file's bytes are the document.** No trailing newline, no framing, no wrapper, so the
`sha256` the manifest records is a digest of the file itself. A `hash` vector's file is a canonical
document (§3), and its `digest` is the pipeline hash of that document (§7.1) — which, because the file
is canonical, is also `sha256:` and the file's own `sha256`. An `accept` vector's file is deliberately
not canonical; its `canonical` member is the canonical document a reader reads it as, and its `digest`
that document's hash.

`manifest.json` is the exception: an LF-terminated index for people, not itself a specified shape.

## Certifying

1. Run every vector, doing what its `kind` says (§9.1):
   - `hash` — decode and re-encode, byte-identical; mint the pipeline hash; it equals `digest`.
   - `reject` — your reader refuses it, for the class `reject` names (§10).
   - `accept` — your reader reads it; re-encoding gives `canonical`, and minting gives `digest`.
2. Assert the number of vectors you ran equals the number `manifest.json` enumerates.
3. Prove once that a mutated document makes your harness go red.

## How the corpus is made

The round-trip and hash vectors are generated by a conformant implementation (Appendix B of the text)
from its wire-surface harness: one document per case of every kind and registry it emits, so a kind
added to the implementation moves the generated corpus and cannot be left out of it. The reject and
accept vectors are authored, each with the refusal or the reading the implementation gives it. The
manifest's `generator` member is the command that regenerates the set. A regeneration is reviewed as a
diff: a digest that moves when no rule changed is the thing this corpus exists to catch.
